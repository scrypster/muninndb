# Hard invariants

Testable assertions a PR must never violate. Anchors are on `develop`. When an anchor's
line number drifts, the symbol name is the source of truth — re-locate by grep, don't
trust the number. If the live code disagrees with an assertion here, the code wins: flag
the stale invariant, don't enforce it.

Format: **[INV-n]** assertion — `file:anchor` — *why it matters / what breaks if violated.*

## Cognition invariants

- **[COG-1]** Unknown preset name falls back to `default`, never errors — `internal/auth/plasticity.go` `ResolvePlasticity`. *Config can never wedge the engine.*
- **[COG-2]** All plasticity overrides are clamped, never rejected (HopDepth 0–8, weights 0–1, ACTRDecay 0.01–2.0, HebScale 0–50, PASMax 0–10, **AssocHalfLifeDays 0.5–3650**) — `plasticity.go`. *Out-of-range config is impossible, not merely discouraged.* For `assoc_half_life_days`, `0` means **unset** (fall through to the preset), not "clamp to the minimum" — pinned by `TestResolvePlasticity_HalfLifeClamped`.
- **[COG-3]** The `working` preset equals `default` plus exactly `{RetentionDays:7, BehaviorMode:selective}` — pinned by `TestResolvePlasticity_WorkingEqualsDefaultPlusTwoDeltas` (`plasticity_test.go`). *Editing `default` must not silently drift `working`.*
- **[COG-4]** All presets share `RecallMode="balanced"`, `ArchiveThreshold=0.05`, `InlineEnrichment="caller_preferred"`, `EnrichmentEnabled=true`, `MaxEngrams=0`, `ScoringFusion=""` — `plasticity.go` preset table + the preset-invariant test suites. *These are cross-preset guarantees other code relies on.*
- **[COG-5]** The ACT-R content gate is `contentMatch = w.SemanticSimilarity*vectorScore + w.FullTextRelevance*normalizedFTS`, where `w` is the **resolved** weights (`resolvedWeights` — from the request/plasticity, falling back to `DefaultWeights{Semantic:0.35, FullText:0.25}` only when `req.Weights == nil`) — `internal/engine/activation/engine.go` `computeACTR` + `resolveWeights`. *The content gate is weight-driven, not a fixed constant. When no weights are supplied, the 0.35/0.25 defaults apply and unused components' budget is redistributed (the `1/0.65` scale). A change to `DefaultWeights` or to the resolve/redistribute logic reshapes scoring for every request that doesn't pass explicit weights — verify against the live `resolveWeights` before asserting what the effective weights are.* **Amendment (S1):** an explicit filter defines the candidate SET; the relevance threshold only RANKS within it. Two mechanisms enforce this for candidates that matched an explicit tag filter (`inTagPool`, verified by `passesMetaFilter`), both in `internal/engine/activation/engine.go`: (1) a content-match floor (`tagMatchFloor`) in `computeACTR` gives tag-only hits a sensible positive ordering below genuine content matches; (2) a **threshold bypass** at every Phase-6 scoring cut-site (RRF, CGDN, ACT-R, and legacy weighted-sum paths) — `if final < req.Threshold && !inTagPool` — so an explicit filter match is never dropped for scoring below the relevance threshold. The floor ALONE is insufficient: a floored, content-unrelated, decayed tag hit scores ≈`0.1 * softplus(B~0.17) ≈ 0.017`, below both the ACT-R default threshold (0.05) and the MCP surface default (0.5), so without the bypass every such candidate was still silently dropped. Before this, a content-unrelated tag hit produced `contentMatch = 0` under default (ACT-R) scoring, which zeroed `final` and dropped a candidate the caller explicitly asked for via `tags_all`/`tags_any`/`tag_prefix` — breaking `due:<=today` reminders whose content is unrelated to the query. See `computeACTR`, the four cut-sites in Phase-6 scoring, and `TestComputeACTR_TagPoolFloor_*` / `TestRawTagRange_SeedsDueItems_DefaultScoring` (which asserts 12/12 due items surface at BOTH production default thresholds). The bypass is safe at every site because each is guarded by `passesMetaFilter` first — only candidates that genuinely match the filter bypass the threshold. Non-tag candidates are still thresholded normally.
- **[COG-6]** The effective default threshold is mode-aware and decided in exactly one place per path, keyed on the **effective scoring mode**, not vault config: the `activateCore` coerce runs AFTER the weights block and tests `actReq.Weights.UseRRFFusion` — for rrf-scored requests it leaves `Threshold` at `0` ("unset") so `activation.Run()` applies rrf → 0.001 (#590); otherwise `activateCore` applies 0.1 (ACT-R/weighted_sum-calibrated). Keying on the effective scoring mode (rather than `resolved.ScoringFusion`) keeps the threshold default consistent with the scoring math that actually runs even when a caller passes explicit weights on an rrf vault (vault config says rrf, but caller-weights requests score ACT-R and must get the 0.1 default) — `internal/engine/engine.go` `activateCore`, `internal/engine/activation/engine.go` `Run`, `internal/mcp/handlers.go` `handleRecall`. An explicit caller threshold is never modified at any layer. Pinned at the **engine** layer (not `Run()`) by `TestActivate_RRFDefaultThreshold_EndToEnd` (`internal/engine/engine_rrf_threshold_test.go`) plus its ACT-R control `TestActivate_ACTRDefaultThreshold_Unaffected`. *R1 (#590 follow-up): before this, `activateCore` unconditionally coerced `Threshold==0 → 0.1` BEFORE `activation.Run()` ever saw the request, making #590's mode-aware default (rrf → 0.001) dead code on every production transport (MCP, REST, gRPC, MBP, embedded) — RRF vaults returned silently-empty default recall. The pre-existing `Run()`-level regression test (`TestRRF_ReturnsResultsWithDefaultThreshold`) stayed green throughout because it calls `Run()` directly with `Threshold: 0`, a call shape production never produces — exactly why the new pin lives at the engine layer instead.* MCP additionally: when the `threshold` arg is omitted, `handleRecall` consults the vault's `ScoringFusion` and passes `0` through (not its historical flat `0.5` prefill) for rrf vaults — and likewise passes `0` whenever a recall `mode` is present, because the mode's preset replaces the 0.5 default and resolving it is the engine's decision; an explicit caller-supplied threshold at or above 0.01 against an rrf vault that returns zero results gets a loud hint (never a silent, unexplained empty), not a clobbered value. **Amendment (#704):** recall-mode presets were a SECOND threshold decider that bypassed the mode-aware default — transports stamped ACT-R-calibrated preset thresholds (semantic 0.3, recent 0.2, deep 0.1) into the request, and the engine's vault-default `recall_mode` block overrode the leave-0-for-rrf decision, so a mode-carrying recall on an rrf vault was still silently empty. Now the ENGINE is the single preset decider: transports (MCP `handleRecall`, REST `handleActivate`) validate the mode name and forward it on the wire (`ActivateRequest.Mode` — previously silently dropped for raw MBP/embedded callers, now honored; gRPC's proto carries no mode field, so that surface is unchanged, and an invalid mode from a raw wire caller is silently ignored — fail-open on presentation, matching the engine's total-ignore of the wire field before; transports rejected invalid modes then and now). The engine resolves the preset in `recall_mode_preset.go` + the weights block, where the effective scoring mode is known: under rrf fusion the preset threshold ABSTAINS (Threshold stays 0 → `Run()`'s rrf floor); preset hops apply unless the caller set `MaxHops` or explicitly `DisableHops`. Preset WEIGHTS have three deliberate cases: (1) explicit weight-carrying mode (`semantic`/`recent`) with no caller weights → the preset defines the FULL weight vector from the ZERO base — the exact struct transports used to stamp — because the preset zero-value scheme cannot express semantic's implicit "decay/hebbian/access/recency = 0", and overlaying resolved defaults lets a fresh, recently-active engram score ~0.7 under legacy scoring with zero content match, above semantic's own 0.3 threshold (silently-wrong-results class, caught in this increment's refute); (2) caller weights present (any mode source) → preset fills only wire-zero fields, caller-set fields always win; (3) vault-default mode with no caller weights → the vault's resolved weights stand and only the `DisableACTR` strategy bit applies (a background default tints, it does not respecify scoring — byte-preserving develop's effective behavior on that path, where resolved-side zero-guards made the scalar fill a no-op). Presets never change the FUSION mode (`UseRRFFusion` comes from vault config or genuinely caller-explicit weights — previously, a weight-carrying preset stamped client-side silently flipped an rrf vault to weighted-sum scoring); on non-rrf vaults an explicit weight-carrying mode does select its scoring STRATEGY (the zero-base vector carries the preset's `DisableACTR` bit), exactly as its stamped form always did. `balanced` means engine defaults: the engine skips it, and MCP keeps its historical 0.5 surface default for it. Pinned by `TestActivate_RRFVaultDefaultRecallMode_NotSilentlyEmpty` (RED without the abstention), `TestActivate_RRFExplicitWireMode_ThresholdAbstains`, `TestActivate_ACTRVaultDefaultRecallMode_PresetThresholdUnchanged` + `TestActivate_ACTRExplicitWireMode_AppliesPreset` (ACT-R paths unmoved / wire mode honored), and the transport wire pins `TestHandleRecallModeForwardedNotStamped` (MCP, RED before: `Mode==""`, `Threshold==0.1`) and `TestActivate_ModeForwardedNotStamped` (REST).

- **[COG-22]** Post-pipeline injection is gated and supersession substitutes atomically under the caller's view. - **[COG-24]** `full_text_relevance` is an **absolute, query-calibrated coverage score in [0,1]**: `Score(d) = (Σ_t idf_t'·cov_t(d)) / (Σ_t idf_t')`, where `t` ranges over the query's deduplicated, tokenized (stemmed-or-raw) content terms; `cov_t(d)` is term `t`'s field-weighted BM25 coverage in doc `d`, capped at 1 (`min(1, Σ_fields tfNorm·fieldWeight/(k1+1))`); and `idf_t'` is the term's real IDF, except a term with **no corpus term-stats entry at all** (`getIDF` returns 0 — the corpus has never seen it), which is charged `idfMax = ln((N+0.5)/0.5 + 1)` — the IDF the term would have at the maximum possible rarity (df=0) for this corpus size — and contributes 0 to the numerator. The denominator depends **only on the query and the corpus's IDF statistics, never on the result set** (no per-query-max normalization) — `internal/index/fts/fts.go` `Search`/`searchTokenCoverage`. Consequently the recall threshold is a genuine abstention gate: a query whose candidates all score below threshold returns empty, and matching only a common token cannot clear a default threshold by itself. The legacy stemmed/raw dual-path union (for vaults not yet reindexed, `FTSVersionKey`) is treated as **one term group per query word**, not two: a genuinely absent word is charged `idfMax` exactly once regardless of how many index-path forms were tried, but each form that DOES have real postings still contributes its own coverage (both forms can carry real, independent postings on a mixed legacy/reindexed vault — `TestFTS_DualPathSearch`). Pinned by `internal/index/fts/calibration_test.go` (single-common-token low relevance, full-coverage high relevance, absent-term-uses-idfMax, and the anti-per-query-max independence pin) and the end-to-end RED/GREEN pair in `internal/engine/activation/fts_abstention_test.go`. *#711: before this, `full_text_relevance` was `math.Tanh(raw unbounded BM25)` (three call sites in `internal/engine/activation/engine.go`: `computeComponents`, `computeACTR`, and the RRF-path reporting site) — raw BM25 runs 2–40 in practice and tanh saturates by x≈3, so a single common word (bm25≈5) reported ≈0.9999, indistinguishable from a genuine multi-term match, and a query term absent from the corpus was silently skipped (`idf<=0 → continue`) rather than penalizing. - **[COG-25]** Heuristic currency is **advisory-only**. The recall-time version-cluster detector (`internal/engine/engine_currency.go` `applyCurrencyAnnotation`, #712/#716) never removes, demotes, score-changes, writes, stamps, links, or confidence-penalizes any result; it only **annotates** (`possibly_superseded_by` / `version_cluster` / `newest_of_cluster` / `cluster_size`) and may reorder **exact score ties within a single detected cluster**, newest-`EffectiveValidFrom`-first. The reorder is a localized post-pass over each equal-score run that permutes only the slots already occupied by one cluster's tied members (`currencyReorderTieRun`) — it moves no non-member and changes no truncation membership; the base sort is a pure total order (`Score` desc, `ULID` asc) so ordering stays transitive and run-to-run deterministic (#699). An explicit `RelSupersedes` (evolve / link) **always wins and suppresses the heuristic entirely for every engram it touches, on BOTH sides of the chain** (`currencyInDeclaredChain`, R4/#757-follow-up): an engram carrying any `RelSupersedes` edge in either direction is excluded from heuristic clustering altogether, so it can neither receive `possibly_superseded_by` nor be crowned. The pre-R4 rule suppressed only the asserted *pair* (plus a crown re-check at emission) and therefore left the declared **successor** — the head of an evolve chain, which carries no incoming stamp — indistinguishable from an un-versioned engram, letting an arbitrary newer unverified memory be crowned over it. That is measured-false-advisory case 3. A future-`ValidFrom` member is never crowned `newest_of_cluster`. Clustering requires, on **every** path: temporal separation, a cosine sanity floor, **competing version-marker sets** (`currencyVersionMarkerGate` — a UNIVERSAL gate since R4; it previously lived inside the tag anchor, which the entity and `RelRefines` anchors bypass by returning early, so two memories sharing one rare entity and no version vocabulary at all could be clustered — measured-false-advisory cases 1/2/4), **no exclusive facet tag at df≥`currencyFacetDF`**, and a shared **topic** anchor (≥2 shared non-ubiquitous tags, or a shared rare entity, or a `RelRefines` edge — anchors substitute for the shared-tag test only, never for version vocabulary); "ubiquitous" is **self-derived per vault** as `max(currencyUbiquityRatio·N, currencyUbiquityAbsMin)` (the absolute floor is #11: a tag on <10 memories is never ambient regardless of vault size), and a tag-df lookup failure fails **toward silence** (returns a large df → the tag is dropped as ambient AND vetoes as a facet), never toward a fabricated cluster. Annotations/`newest_of_cluster` are computed over the **co-retrieved result set only** (same returned-set boundary as the authoritative `SupersededBy`). Surface scope: MCP + MBP annotations only (matching the pre-existing `superseded_by` scope; REST inherits via type alias; proto/gRPC/SDK carry no supersession annotations). Pinned by (all RED-checked) `TestCurrencyAnnotation_ExplicitSupersedesCrown_NoTransitiveLeak`, `..._DigitPrefixedFacet_NotExemptFromFacetVeto`, `..._TieBreak_TransitiveAcrossClusterBoundary`, `..._FacetConflict_IsLoadBearing`, `..._TemporalFloor_/CosineFloor_/TagShareMin_…NotClustered`, `TestCrossVault_SmallVault_SelfDerivedUbiquity_ChainClusters`, `TestCurrencyUbiquityCutpoint`, and the R4 precision suite `TestCurrencyPrecision_EntityAnchorSideDoor_UnrelatedTopics` / `..._RelRefinesSideDoor_NoVersionVocabulary` / `..._DeclaredSuccessor_NotAdvisedSuperseded` / `..._AdjacentTopics_NoBroadHints` / `..._GateAttribution` (`internal/engine/engine_currency*_test.go`), plus the cross-vault safe-silence corpus. *No mechanical signal can prove "B replaces A" vs "B supplements A" — that is a judgment about the world (the five-analysis impossibility result); this phase supplies a high-precision hint and the querying agent supplies the judgment.*
- **[COG-26]** `semantic_similarity` is an **absolute, model-calibrated relevance in [0,1]**: `semCal = max(0, (cos − b)/(1 − b))` where `cos` is the raw cosine returned by the vector index and `b` is the embedding model's measured anisotropy noise baseline, resolved from a per-embedder registry (`internal/plugin/embed/baseline.go`, `NoiseBaseline`/`Rescale`) keyed by the vault's embed model. Model resolution order (`internal/engine.(*Engine).resolveSemanticBaseline`): (1) the per-vault plasticity override `SemanticFloor`/`SemanticFloorOverride` (explicit `0` disables the floor; an out-of-range value ≥1 is rejected with a WARN and falls through, never silently zeroing every match); (2) the vault's recorded embed model (`store.GetEmbedModel`) if set, else the engine's process-wide `EmbedModelName` (resolved once at startup from the active provider, `cmd/muninn/server.go` — for the bundled zero-config default this is `"bge-small-en-v1.5"`, registered at `b=0.520`); (3) the registry lookup itself. **A model with no registry entry — including empty/unknown, e.g. a vault whose embed-model marker was never populated and no process-wide model was wired — gets the identity transform (`b=0`) plus a one-time-per-model WARN, never a guessed floor** (#582/#585/#589: explicit config is honored or fails loudly, never silently substituted). Applied at the three sites where `w.SemanticSimilarity*vectorScore` feeds `contentMatch`/`raw` (`internal/engine/activation/engine.go`: `computeComponents`, `computeACTR`, and the RRF-path reporting site — the same trio COG-24 touched for tanh; `computeGatedActivation`/CGDN inherits the calibrated value for free by reusing `computeComponents`'s output rather than recomputing it, per the reuse-proven-mechanisms principle). `FullTextRelevance` is untouched (already calibrated by COG-24). Reported `score_components.semantic_similarity` is the CALIBRATED value (`semCal`, not raw cosine) — mirrors COG-24's `full_text_relevance` semantics — and `score_components.semantic_similarity_raw` carries the uncalibrated cosine alongside it at every site (the honesty backstop: an operator debugging a wrongly-abstained match can see the raw cosine, e.g. 0.59, next to the calibrated value that made it abstain, e.g. 0.07, without a second tool call). Consequently the ACT-R content gate (`engine.go` line ~1931: "zero semantic relevance = zero score regardless of recency") now gates semantic nonsense the same way COG-24 gates lexical nonsense, and corroborated weak matches survive by construction — FTS coverage still adds to `contentMatch`, Hebbian/transition boosts still multiply the prior. Pinned by: the bge-small registry-constant value; `internal/engine/activation/semantic_abstention_test.go` (RED-sanity with `SemanticBaseline=0` reproducing the pre-fix leak on a real bge-small embedder + real cosine, GREEN with `SemanticBaseline=0.520`, positive controls proving a genuine high-cosine match and a genuine paraphrase both still clear the floor as hard assertions — not skips, see below — a dedicated 0.60–0.65-band genuine-match pin, and a small-vault (~18 engram) zero-lexical-overlap probe); the rescale is monotone in `cos` (`Rescale`/`rescaleSemantic`), so RRF ranks are provably unchanged and genuine orderings cannot invert.
  *#711/COG-26: this closes deferral (1) from COG-24 ("the semantic-similarity floor — weak-but-nonzero cosine similarity between unrelated texts (embedding anisotropy) still floats some irrelevant results"): bge-small-en-v1.5 out-of-domain query↔passage cosine runs μ=0.450/σ=0.054 (432 pairs), clearing the 0.1 ACT-R threshold on noise alone (0.6×0.5=0.30).*
  **Honest history — b was revised down after a real regression, not tuned in the abstract.** The value landing with this increment was originally `b=0.558` (μ+2σ). An adversarial refute (2026-07-29) proved that value too aggressive using a real bge-small embedder, not a synthetic one: at `b=0.558` the sem-only survival bar — the raw cosine below which `contentMatch` can never clear the 0.1 gate with zero FTS/tag/Hebbian corroboration — sits at `0.558 + 0.1667×(1−0.558) ≈ 0.632`. A genuine paraphrase measured at cosine 0.59 scored `contentMatch = 0.043 < 0.1` and **recall returned EMPTY** where the match should have ranked #2. Modeling the true-pair cosine distribution as μ=0.693/σ=0.088, roughly 24% of genuine matches fell below that 0.632 bar. The regression was previously mischaracterized in this entry as *only* a large-vault HNSW-pool-loss ranking issue (see the named residual below) — that is real, but it is not the whole story: **the floor itself, independent of any pool-loss, silently removes in-pool, otherwise-uncorroborated genuine matches below its own survival bar.** On a large, mature vault this is often masked (the same weak match is frequently outside the `K=⌊√N⌋` HNSW candidate pool anyway, so the floor isn't the proximate cause of its absence); on a small or fresh vault — a new user's first session, a narrow single-topic vault — there is no such masking and no FTS/tag/Hebbian corroboration to fall back on, so the floor is the sole gate and a too-high `b` is a genuine, measurable recall regression, not a theoretical one.
  `b` was lowered to **μ+1.3σ = 0.520**, which drops the survival bar to `0.520 + 0.1667×(1−0.520) ≈ 0.600`. This rescues the refute's 0.59-cosine case and the broader 0.60–0.65 band while still abstaining the measured noise ceiling (the highest observed out-of-domain cosine in the 432-pair measurement, ≈0.596, "quarterly ballet recital"-shaped queries against an unrelated corpus) — but the margin there is **thin**: at `b=0.520`, cosine 0.596 rescales to `semCal=(0.596−0.520)/0.480≈0.158`, `contentMatch=0.6×0.158≈0.095`, which clears the abstention gate by only ≈0.005. This is not "zero net regression" and this entry does not claim it is. **The band `cosine ≤ noise-top (~0.596)` is IRREDUCIBLE at the model-anisotropy level**: no flat, per-model scalar floor can separate a genuine match from noise inside a range where the two distributions overlap — raising `b` re-introduces the false-abstention this refute found; lowering it further shrinks the false-abstention band but shrinks the noise-rejection margin further, and eventually lets noise back in. This is an accepted precision/recall trade, made as explicit, bounded, and reviewable as this paragraph — not a hidden cost. **The recourse for a vault that needs a different point on that curve is the per-vault plasticity `SemanticFloor` override**, not a global re-tune.
  **Named residual (ranking, not abstention, NOT fixed by this increment):** genuine weak paraphrases to memories with a large in-domain candidate pool can *additionally* lose the `K=⌊√N⌋` HNSW pool to in-domain-adjacent noise and be prior-suppressed even when pooled — a monotone per-candidate rescale cannot change cosine order or pool membership, so this is a corroboration/retrieval-coverage problem (entity/association expansion, larger pool + rerank), not something a baseline floor can address, and it compounds with (does not replace) the floor's own irreducible sub-band above. **Also deferred, named honestly:** (1) a per-vault empirical calibration command (`muninn vault calibrate`) for embed models outside the registry, instead of falling back to identity+WARN forever; (2) the weighted-sum path's additive recency/decay reachable without content match (COG-24 deferral (2)) still floats independent of this floor; (3) RRF-mode abstention remains structurally impossible (COG-24 deferral (4)), unaffected by this change.

- **[COG-27]** **Association decay is cadence-independent and never raises a weight.** For every 0x03 edge, `DecayAssocWeights` computes a peak-anchored elapsed-time ceiling and clamps under it: `Δt = max(0, now − anchor)`, `ceiling = max(peakWeight·0.05, peakWeight·2^(−Δt/H))`, `w_new = min(w_old, ceiling)`, where `H` is the vault's resolved `AssocHalfLifeDays` and `anchor` is `lastActivated`, falling back to `createdAt`, falling back to *adoption* (stamp `lastActivated = now`, leave the weight alone) — `internal/storage/association.go`. Both inputs already live in the 26-byte association value: **no value-format change, no new Pebble prefix, no migration.** Consequences, each pinned:
  - Two evaluations at `t₁ < t₂` with no intervening activation produce the weight of a single evaluation at `t₂` to within `assocDecayWriteEpsilon` — the write-skip can leave the stored weight up to one epsilon above the true ceiling, never below it (`TestDecayAssoc_CadenceIndependent`). The prune worker's ~60 s period is therefore a responsiveness choice, not a term in the decay rate. *Before #762 it was the unit: `0.95` per pass at 1329 passes/day meant a ~15-minute half-life, and the store-wide maximum association weight was the 0.05 floor.*
  - Decay never increases a weight (`TestDecayAssoc_NeverRaisesWeight`, `..._FutureLastActivated_NeverBoosts`, `..._SubFloorStaleEdge_NotRaisedToFloor`). Two guards make this structural rather than policy-checked (principle #3): the drop guard (`drop = w_old − ceiling`, write nothing unless `drop >= assocDecayWriteEpsilon`) covers every path where `w_new` is the ceiling, and the post-floor guard (`newW >= oldW` after the floor/archive block ⇒ no write, excluding archive promotion and the no-peak delete path) covers the floor branch, which ASSIGNS `dynamicFloor` and could otherwise raise a sub-floor weight — reachable, since the dream engine writes inferred weights through `UpdateAssocWeight` under a monotone peak. The same guard is what stops a floored edge from being rewritten (5 keys + a replicated batch) every pass forever (`TestDecayAssoc_FlooredEdge_NoRewriteChurn`). Together they leave no path that can write an increase. It also means **#762's existing damage is not undone** — floored edges stay floored and re-learn through Hebbian growth rather than being resurrected by fiat.
  - `lastActivated == 0` means *unknown*, never *the Unix epoch* (`TestDecayAssoc_LegacyZeroLastActivated_Adopted`). Read as an epoch stamp the formula floors every legacy edge on its first pass.
  - The `assocDecayWriteEpsilon` (0.001) write-skip forgives no decay: it is a **bounded lag, not accumulated error**, because every pass recomputes from the anchor instead of compounding off the stored weight. Measured at ≤ epsilon after both 1,329 and 39,876 skipped passes (`TestDecayAssoc_EpsilonSkipLagIsBounded`).
  - Restart- and downtime-immune, and convergent under replication: the ceiling is a pure function of `(peakWeight, lastActivated, now)`, the first two replicate, and `min` is commutative and associative. This **does not close #760** — the worker is still role-blind and writes still race — but independently-scheduled nodes now converge to `min` over the union of their evaluation times instead of diverging by pass count.
  - **Dependency:** the mechanism is only as good as `lastActivated`. `UpdateAssocWeight`/`UpdateAssocWeightBatch` stamp it; `DecayAssocWeights` deliberately does not. Any future path that writes an association without stamping it becomes a silent "this edge never fades" bug.
  - **Named residual:** `lastActivated` is `int32` (2038 overflow). Post-2038 `Δt` goes negative, the guard clamps it to 0, and decay silently *stops* — fail-safe in direction, but it needs widening, which is a value-format change.

## Security & transport invariants

- **[SEC-1]** A `cap_` token must never set `IsAPIKey` — exactly one of `IsAPIKey`/`IsCapability` is set — `internal/mcp/context.go`, `internal/mcp/types.go`. *This is what makes the recursion guard structural.*

- **[SEC-7]** A vault-pinned credential rejects any differing `vault` argument and never echoes the pinned name — `internal/mcp/context.go` (also REST/gRPC/MBP). *No cross-vault action, no name leak.*

- **[SEC-13]** Any new client write path in a cluster deployment must either gate on `IsLeader()`/Cortex-origin or replicate its mutation — no transport does this today, which is exactly bug #596. Background workers that mutate replicated state (e.g. the pruner) inherit the same obligation.
- **[SEC-14]** The elevated trust level `verified` (human-confirmed / admin-certified) can only be set on a write by a caller whose ctx `auth.ContextMode` is `full` or `write` — an `observe` credential is rejected with `ErrInvalidRequest`, never silently downgraded — `internal/engine/engine.go` `resolveTrust`.
